# 🏕️ Aventura 360

**Aventura 360** es un proyecto desarrollado para la asignatura **Taller Integrador** de la carrera **Licenciatura en Sistemas de Información** de la **Facultad de Ciencia y Tecnología (UADER)**.

El proyecto propone el desarrollo de una **plataforma web orientada al rubro outdoor**, permitiendo centralizar la gestión y comercialización de productos relacionados con actividades al aire libre, aventura y recreación.

---

## 🎯 Objetivo del proyecto

El objetivo de Aventura 360 es desarrollar una solución web que permita administrar de manera integral un comercio del rubro outdoor, brindando funcionalidades tanto para los clientes como para los responsables de la administración del sistema.

El proyecto busca integrar los conocimientos adquiridos durante la carrera, aplicando conceptos relacionados con:

- Análisis y diseño de sistemas.
- Ingeniería de software.
- Diseño de interfaces.
- Modelado de datos.
- Desarrollo frontend y backend.
- Gestión de proyectos.
- Control de versiones.
- Trabajo colaborativo.

---

## 🧩 Funcionalidades previstas

### 👤 Cliente

- Registro e inicio de sesión.
- Visualización del catálogo de productos.
- Búsqueda y filtrado de productos.
- Consulta del detalle de cada producto.
- Gestión del carrito de compras.
- Gestión de datos personales.
- Generación de pedidos.
- Consulta del estado de los pedidos.

### ⚙️ Administración

- Gestión de productos.
- Gestión de categorías.
- Gestión de stock.
- Gestión de usuarios.
- Gestión de pedidos.
- Actualización del estado de los pedidos.
- Administración de información relevante del sistema.

> Las funcionalidades pueden modificarse o ampliarse durante el desarrollo del proyecto de acuerdo con los requerimientos y las distintas etapas de análisis.

## 📋 Metodología de trabajo

El desarrollo del proyecto se realiza de manera **incremental e iterativa**, dividiendo el trabajo en distintas etapas.

Para la organización del equipo se utilizan herramientas de GitHub que permiten:

- Gestionar tareas.
- Registrar issues.
- Organizar el trabajo mediante un tablero Kanban.
- Asignar responsables.
- Utilizar ramas para el desarrollo de funcionalidades.
- Realizar Pull Requests.
- Mantener un historial de cambios mediante commits.

## 📂 Organización del repositorio
